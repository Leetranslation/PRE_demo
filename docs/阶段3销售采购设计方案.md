# 阶段3 销售/采购补全 设计方案（待确认）

> 用途：阶段3 销售+采购 13 个单据的字段、流程、级联关系设计，确认后开发。
> 决策：销售+采购全做、交替推进、完整单据（含审批流转+关联下游生成）。
> 核心原则：**销售与采购是镜像关系，通过 MRP 交汇，设计时保持对称。**

---

## 一、销售 ↔ 采购 关联全景（开发前必读）

```
销售主线：报价单 → 合同 → 销售订单 → 销售出库 → 销售发票 → 销售核销(收款)
采购主线：采购申请 → 询价单 → 采购订单 → 采购入库 → 采购发票 → 采购核销(付款)
                              ↑
                   MRP（销售订单/工单触发 → 采购需求）
```

### 镜像关系表（对称设计）

| 销售侧 | 采购侧 | 说明 |
|---|---|---|
| 报价单 quotation | 询价单 inquiry | 销售报价给客户 / 采购向供应商询价 |
| 销售订单 sales_order | 采购订单 purchase_order | 已存在 ✅ |
| 销售出库 sales_outbound | 采购入库 purchase_inbound | 已存在 ✅ |
| 销售发票 sales_invoice | 采购发票 purchase_invoice | 开票给客户 / 收供应商发票 |
| 销售核销 sales_verification | 采购核销 purchase_verification | 收款 / 付款 |
| 销售退货 sales_return | 采购退货 purchase_return | 客户退回 / 退回供应商 |
| 售后管理 after_sale | —（无对应） | 销售独有 |
| 销售备货单 sales_stocking | 采购申请 purchase_requisition | 备货 / 采购需求申请 |
| 设计中心 design_center | —（无对应） | 销售独有（生成BOM） |

## 三、统一设计规范（所有单据遵守）

1. **审批流转**：`pending → approving → approved`，反审核回 `pending`，禁止自审（沿用现有 `checkSelfApprove`）
2. **金额计算**：差额法倒挤税额（沿用现有 `saveItems` 逻辑）
3. **编号规则**：`前缀 + yyyyMMdd + 4位流水`（前缀见上表）
4. **级联校验**：下游单据反审核前，检查是否已产生更下游的单据（如发票已核销则不能反审核发票）
5. **禁止超量**：发票金额 ≤ 订单未开票金额、核销金额 ≤ 发票未核销金额、退货数量 ≤ 已入库数量

---

## 四、关键级联规则（销售采购交汇点）

| 级联 | 规则 |
|---|---|
| 报价单/合同 → 销售订单 | 审核通过后可生成，生成后标记「已转单」 |
| 销售订单 → MRP → 采购订单 | 已有 `MrpConfirmService`，销售订单审核后触发 MRP，生成采购需求 |
| 采购申请 → 采购订单 | 申请审核后转采购订单 |
| 销售/采购发票 → 核销 | 发票可多次核销，累计核销 ≤ 发票金额 |
| 退货 → 库存 | 销售退货 = 库存入；采购退货 = 库存出（方向相反，镜像） |

## 五、建议开发顺序（交替推进，保持镜像）

```
第1批：报价单(销售) + 采购申请单(采购)   —— 两条线的起点
第2批：合同(销售) + 询价单(采购)
第3批：销售发票 + 采购发票（镜像，可同批）
第4批：销售核销 + 采购核销（镜像，可同批）
第5批：销售退货 + 采购退货（镜像，涉及库存）
第6批：售后管理、销售备货单、设计中心、装箱单（销售独有）
```
