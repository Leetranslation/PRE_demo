## 四、开发约定（强制，违反会返工）

1. **代码改到哪，文档记到哪**：每改一次代码/库/接口，必须同步更新 `开发总进度.md`（进度）+ `API接口规范.md`（接口）。
2. **交付顺序固定**：建表 SQL → Entity/Mapper → DTO → Service → Controller → 前端 api.ts → 路由+菜单 → vue 页面。
3. **权限码**：同步登记到 `DataInitializer.java`。
4. **完成判据 = 关联闭环**，不是「接口返回成功」。
5. **三层测试**（开发完必做，测完清理脏数据）：
   - 第一层：单功能测试（CRUD、状态流转）
   - 第二层：关联测试（本模块改了谁的状态、谁依赖本模块的状态、是否校验上游状态）
   - 第三层：边界/异常测试（超量、越权、状态不符、时间冲突等）
6. **开发前先梳理「数据流/关联影响图」**：数据从哪来、改了什么、谁读它、谁依赖它状态。

## 五、关键技术决策与「坑」（务必遵守）

### 5.1 统一返回与分页
- 统一 `Result<T>`、`PageResult<T>`，异常走 `BizException` + `GlobalExceptionHandler`。

### 5.2 编号规则
- 统一 `CodeGenerator`：**前缀 + yyyyMMdd + 4 位流水**。
- 已登记前缀见 `开发总进度.md`（GX 工序、BW 报工、PC 排产、MP 主生产计划、BJ 报价、SQ 采购申请、HT 合同、XJ 询价、FP 发票、HX 核销、TH 退货、SH 售后、BH 备货、SJ 设计、ZX 装箱、QTR/QTC 其他出入库、QS 质检申请 等）。

### 5.3 时间序列化
- 实体里 `LocalDateTime` 字段**必须加** `@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss")`，否则前端收到乱格式。

### 5.4 工单状态机语义（重要！）
- **审批通过 ≠ 开始生产**：`approve()` 后 `bizStatus` 保持 `pending`（未开始），由 `start()`（工单开始）才转 `producing`（执行中）。
- 7 态：`pending` / `producing` / `near_overdue` / `overdue` / `finished` / `completed` / `voided`。
- 子状态字段：`finish_status` / `inbound_status` / `issue_status` / `qc_status` / `machine_status` / `urgency` / `outsource_status`。
- 状态操作接口：`start` / `finish` / `void`。

### 5.5 完工口径
- **只有最后一道工序的良品**才累加到工单 `completedQty`（成品数量）。非最后工序报工不增加 `completedQty`。

### 5.6 报工 / 排产的上游校验
- 报工：校验工单「已审批 + 执行中」。
- 排产：校验工单「已审批」，且**机台时间冲突检测**（同一机台时间重叠拒绝）。

### 5.7 金额管控（销售/采购发票、核销）
- 发票金额 ≤ 订单未开票金额（**含已创建未审批的发票**，防止连续建多张绕过）。
- 核销金额 ≤ 发票未核销金额（含累计未审批核销单）。
- 审批通过回写 `invoiced_amount` / 核销金额，反审核回退。

### 5.8 禁止自审
- V1 安全规则：不允许本人审批本人单据。**测试时需临时开启 `allow_self_approve`**，测完关闭。

### 5.9 测试方式
- 用 Python 脚本测接口（脚本内容 UTF-8，打印中文结果）。
- Swagger 地址见 `README.md`（`OpenApiConfig` 已配置 JWT 鉴权）。
