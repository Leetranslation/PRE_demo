1. 项目概述
1.1 目标
建设轻量级制造业 ERP，打通销售、MRP、采购、生产、库存、质量，形成可追溯业务闭环。
1.2 第一版范围
首页/驾驶舱

销售管理
采购管理
生产管理
MRP/计划
库存管理
质量管理
系统管理
报表
通用审批、权限、附件、Excel、日志、通知
1.3 非目标
第一版不开发 AI 智能下单/交期预测/自然语言问答
不建设复杂财务、OA、人力
不建设复杂 MES 工艺路线、设备排程
不采用微服务
2. 产品边界与原则
页面布局和交互尽量接近提供的企业级 ERP 图片：左侧导航、顶部操作、筛选区、表格、右侧行操作、单据详情结构。
功能不照搬复杂企业 ERP，坚持当前项目轻量化范围。
必填字段只标记真正必要字段，使用 *。
采购、生产等业务统一使用“入库”，不使用“收货”。
所有核心单据支持筛选、分页、导出；允许单条和批量操作。
业务状态变化成功后页面立即刷新数据，不依赖用户手动刷新。
所有库存变化有来源、有流水、可追溯。

6.2 通用字段
核心表建议统一包含 id、业务编号、状态、创建人、创建时间、修改人、修改时间、备注等。基础资料（客户、供应商、物料、产品等）不物理删除，统一采用「启用/停用」；已被业务单据引用的基础资料禁止停用。
6.3 状态原则
审批状态和业务状态分离。审批状态：待提交、审批中、已审批；业务状态按模块定义。
7. 基础资料
7.1 客户档案
必填：客户编号、名称、分类、状态；非必填：联系人、电话、邮箱、地址、备注、附件。
7.2 供应商档案
必填：供应商编号、名称、分类、状态；非必填：联系人、电话、邮箱、地址、备注、附件。供应商作为采购管理独立子模块。
7.3 物料档案
物料是采购、生产、库存物料的基础身份证。必填：编号、名称、分类、单位、状态。
供应属性：采购/自制/采购+自制
库存管理：是/否；默认仓库/库位；安全库存；最大/最小库存
批次/序列号：不管理/批次/序列号
采购质检：是/否
生产质检：是/否
7.4 产品档案
产品与物料分开；用于销售、生产、成品库存、BOM。必填：编号、名称、分类、单位、状态；可配置库存、批次/序列号、质量、生产属性。
7.5 BOM
支持多层 BOM、版本、生效/失效日期。明细：子物料/子产品、数量、单位、损耗率、工序、备注。生产工单保存实际使用 BOM 版本。
7.6 仓库/库位
仓库包含编号、名称、类型、状态；仓库可包含多个库位。
7.7 字典
物料/产品/客户/供应商分类、单位、采购类型、生产类型、仓库类型、工序等统一维护。
8. 销售管理
8.1 销售订单字段
必填：销售单号（自动）、客户、订单日期、销售类型。非必填：联系人、交货日期、业务员、部门、备注、附件。明细：产品、规格、单位、数量、单价、金额、计划交货日期、备注。
8.2 销售业务
审批通过后库存预留；库存不足形成 MRP 缺口。支持部分出库。
8.3 销售出库
统一操作名称“出库”。明细包含产品、仓库、库位、批次、序列号、数量。
8.4 销售退货
关联原订单/出库单，退货增加库存，必要时进入质量流程。
8.5 筛选
销售单号、客户、产品、日期、交货日期、销售类型、审批状态、业务状态；支持批量提交/审批/反审核/导出。
9. 采购管理
9.1 采购订单字段
必填：采购单号、供应商、订单日期、采购类型。非必填：预计到货日期、联系人、部门、采购员、备注、附件。明细：物料、规格、单位、数量、单价、金额、预计到货日期。
9.2 采购类型
备货采购、生产采购、MRP采购。
9.3 入库
采购订单右侧操作提供“入库”；支持分批入库、批次、序列号、仓库、库位。
9.4 质检
由物料档案采购质检属性决定是否触发。
9.5 采购退货
关联采购入库，退货减少库存。
10. 生产管理
10.1 生产工单字段
必填：工单号、产品、生产数量、生产类型、计划生产日期。非必填：来源销售订单、计划完成日期、生产部门、负责人、备注、附件。
10.2 类型
订单生产、库存生产、MRP生产。
10.3 BOM
选择产品自动带出当前有效 BOM；支持多层展开；工单保存 BOM 版本。
10.4 领料/退料/入库
支持分批领料、退料、生产入库；均产生库存流水；入库是否质检由产品/物料配置决定。
10.5 状态
业务：待生产→生产中→部分完成→已完成。
11. MRP/计划
MRP综合销售需求、库存、预留、安全库存、已有采购、已有生产和多层 BOM。
11.1 MRP流程图
销售需求   ↓展开多层 BOM   ↓计算总需求   ↓扣除：可用库存 + 已采购 + 已生产   ↓形成缺口   ├── 采购属性 → 采购建议 → 采购订单   └── 自制属性 → 生产建议 → 生产工单
采购+自制物料允许选择供应方式。MRP结果保留来源销售订单及下游采购/生产关联。
12. 库存管理
12.1 库存台账
维度：物料/产品+仓库+库位+批次/序列号。指标：实际库存、预留库存、可用库存。
12.2 库存流水
记录采购入库、生产入库、销售出库、生产领料、退货、调拨、盘点、调整等。
12.3 库存数据流图
采购入库 ─┐生产入库 ─┤销售退货 ─┤盘点/调整 ┤ → 库存台账 → 当前库存调拨入库 ─┘       ↓                库存流水销售出库 ─┐       ↑生产领料 ─┤───────┘采购退货 ─┘
12.4 调拨/盘点
调拨支持源仓库→目标仓库；盘点：创建→实际数量→差异→确认→库存调整。所有库存数量变化必须产生库存流水，禁止直接修改库存台账数量；盘点、调整、报废等必须通过对应业务单据产生库存变动。
12.5 批次/序列号
由物料档案决定；序列号一物一码且不可重复。
13. 质量管理
采购入库和生产入库均可按配置触发质检。质检单：单号、来源、对象、数量、日期为核心必填；结果合格/不合格/部分合格。不合格记录原因和处理方式（退货/报废），并据此更新库存状态（可用/待检/不合格），不合格库存不得正常出库或领料。

14.2.2 菜单权限与操作权限
permission 表以 type 字段区分两类权限：
menu（菜单权限）：控制页面能否访问，每个页面一条，path 字段对应前端路由地址。用户持有该权限时，对应菜单项才可见。
button（操作权限）：控制页面内的按钮与写操作，通过 parent_id 归属到所属菜单。
授权规则：
明细查询接口（如各单据的 /items、BOM 的 /versions）不单独授权，跟随所属页面的菜单权限。
公共数据接口（字典、驾驶舱统计、站内通知）不设权限，登录即可访问。
未显式分配的权限一律拒绝，不存在默认允许。
完整权限码清单见数据库初始化脚本 init_data.sql 中 permission 表的初始化数据，不在本文档重复列出。
14.2.3 权限校验设计决策
权限不写入 JWT：令牌仅携带用户标识，服务端每次请求从数据库加载用户权限。好处是权限调整后立即生效，无需等待令牌过期；代价是每次请求增加少量查询。
401 与 403 必须区分：未登录或令牌失效返回 401，前端跳转登录页；已登录但无权限返回 403，前端提示无访问权限。
不使用硬编码旁路：包括管理员在内的所有权限均来自角色配置，代码中不得以角色判断绕过校验。管理员的全量权限由初始化脚本写入，且禁止移除自身的系统管理权限，避免误操作导致系统不可用。
数据权限（全部 / 本部门 / 本人）记录在 role.data_scope 字段，第一版仅作为配置预留，不参与数据查询过滤。

补充规则（本轮需求讨论冻结，追加于原文之后）
42. 价格、税务与金额规则
42.1 V1仅支持人民币（CNY）作为业务单据币种，不建设多币种汇率体系。
42.2 销售和采购单据的单价默认定义为含税单价。
42.3 销售/采购明细保留税率字段，默认税率为13%，允许按明细修改；具体税率以系统配置为准。
42.4 明细金额至少包括：数量、含税单价、不含税金额、税额、价税合计。
42.5 不含税金额 + 税额 = 价税合计；税额按税率和统一金额精度计算。
42.6 数量精度6位小数；单价精度6位小数；金额、税额、价税合计2位小数。
42.7 金额由后端重新计算并校验，前端传入金额不得作为最终可信数据。
42.8 V1不建设应收、应付、发票、总账、成本结转等财务模块；金额仅用于销售/采购业务单据、查询和报表。
43. 审批与反审核冻结规则
43.1 V1采用一级审批，不建设多级审批流引擎。
43.2 审批配置采用"单据类型→审批角色"；审批人来自对应角色成员。
43.3 默认禁止制单人审批自己创建的单据；管理员可通过系统参数显式开启"允许制单人自审"。
43.4 待提交可编辑/删除；审批中普通用户只读；审批通过后核心字段锁定。
43.5 已审批但尚未发生下游业务的单据，可由有权限用户反审核；必须填写原因并记录日志。
43.6 反审核不能绕过业务数据。已产生入库、出库、领料、退料等下游业务的单据，原则上禁止直接反审核；必须先处理对应下游业务，使库存回到合法状态。
43.7 已产生下游单据的核心单据不得直接反审核；系统必须检查下游单据、库存事务和已完成数量，反审核不得破坏历史追溯。
43.8 审批状态与业务状态分开维护；审批通过不等于业务完成。
43.9 批量审批、驳回、反审核逐条返回成功/失败原因。
44. MRP计划规则冻结
44.1 V1 MRP采用"按计划范围进行全局计算"，不以单个销售订单独立计算作为唯一模式。
44.2 用户执行MRP时选择计划日期范围；默认需求来源为范围内已审批销售订单及已确认的其他需求。
44.3 MRP统一汇总同一物料需求，避免多个销售订单分别计算造成重复补货。
44.4 MRP计算考虑库存、预留、已审批采购供应、已审批生产供应、安全库存和多层BOM需求。
44.5 库存明确区分：可用库存、待检库存、不合格库存。待检库存与不合格库存不得计入 MRP 可用库存，也不得用于正常销售出库或生产领料。不合格经处理后，根据处理结果转为可用、退货、报废或其他状态。
44.6 V1支持采购提前期和生产提前期；物料/产品维护提前期天数，MRP据需求日期倒推建议采购日期或建议开工日期。
44.7 V1不建设复杂产能、设备、班次、有限能力排程和APS；提前期仅用于基本日期建议。
44.8 "采购+自制"物料产生缺口后由用户选择采购或自制；选择自制时继续展开有效BOM并形成生产建议。
44.9 MRP建议不直接改变库存，也不自动下采购订单/生产工单。
44.10 用户确认后可批量生成采购订单或生产工单；生成前展示物料、缺口、供应方式、建议日期供确认。
44.11 MRP建议保存需求来源、建议数量、供应方式及最终生成的采购订单/生产工单关联。
44.12 已转换为下游单据的需求再次执行MRP时不得重复生成；只处理真实新增缺口。
44.13 V1不做自动向供应商下单；采购订单由用户确认后生成。
45. 库存成本规则冻结
45.1 V1不计算库存成本，不实现加权平均、标准成本、先进先出等成本核算。
45.2 V1不建设生产成本核算、材料成本结转、销售成本结转、财务凭证。
45.3 库存台账和库存流水预留单位成本、总成本字段，但V1可为空，不参与库存数量计算。
45.4 采购/销售价格属于业务单据金额；库存数量事务不得依赖库存成本字段。
45.5 后续V2成本模块基于库存流水重新设计成本计算，不修改V1库存数量事实。

46.1 销售订单明细：数量、含税单价、税率、不含税金额、税额、价税合计。
46.2 采购订单明细：数量、含税单价、税率、不含税金额、税额、价税合计。
46.3 物料：采购提前期、采购质检属性、供应属性。
46.4 产品：生产提前期、生产质检属性。

补充冻结结论（评审拍板）
A. 价格/金额计算（冻结）
税额舍入（差额法）：明细逐行计算——不含税金额=round(含税单价×数量÷(1+税率),2)；价税合计=round(含税单价×数量,2)；税额=价税合计−不含税金额（保证恒等）。
不含税金额唯一公式：不含税=含税金额÷(1+税率)；税额用减法倒挤，不做循环定义。
税率不做字典：单一可配置默认值13%，明细自由修改。
金额=明细价税合计，不含运费/折扣。
B. 审批（冻结）
审批角色多成员：任一成员审批即通过。
反审核后回「待提交」；V1 不做驳回/退回，只做「审批通过 + 反审核」。
核心字段锁定清单：编号、客户/供应商、明细（产品/物料/数量/单价/税率/金额）、来源单据；备注/附件/交货日期可放开。
C. MRP（冻结）
净需求公式：净需求=max(0, 毛需求+安全库存−可用库存−在途供应)；可用库存=实际−预留−待检−不合格。
在途供应时间过滤：只计入「需求日期前可到货/完工」的供应。
提前期按自然日计；计入损耗率（需求=数量×(1+损耗率)）；不做最小起订量/包装量。
D. 开发决策（冻结）
流水号按日连续自增（每天从 0001 起），删除单据留空号：如 0002 被删除则 0002 永久作废不复用，下一张仍为 0004。
打印 V1 不做。
业务单据不采用物理删除+编号复用。仅「待提交且未被任何下游单据引用」的单据允许删除；删除后编号永久作废，不允许复用。已审批、已入库、已出库、已关联下游单据的单据禁止删除。基础资料不物理删除，统一采用启用/停用；已被业务单据引用的基础资料禁止停用。
登录：用户名 + 密码，无验证码；不对接钉钉/SSO。
初始化脚本创建最高权限超级管理员账号。
技术栈锁定：Java 21 + Spring Boot 3 + MySQL 8 + Redis + Vue3（不得更换组件）。
E. 业务流转（冻结）
销售出库：审批通过后人工点「出库」；V1 不做超期自动释放（不增加后台定时机制）。预留随销售订单存在，订单取消/关闭时释放；后续如需自动释放，按「预留有效期 + 系统定时任务」实现（如预留 7 天到期自动释放并记录日志）。
质检不合格：V1 只做合格 / 退货 / 报废三种结果（暂不做让步接收、返工）。不合格退货联动采购退货/库存减少，报废直接扣减库存。
序列号：入库时生成绑定，出库时从已有序列号里选。
调拨不审批（直接生效）；盘点差异需审批后调整库存。
F. 数据库字段级设计（冻结）
数据库必须做到字段级设计：字段名、类型、长度、是否必填、默认值、索引、主外键、说明。核心表必须详细到字段级，不能只停留在 ER 图。
G. 精度与金额（冻结）
数据库精度固定：数量 6 位小数、单价 6 位小数、金额 2 位小数、税率 2 位小数。V1 不开放用户随意修改数据库精度；税率等业务参数可配置。
H. 库存数量上限（冻结）
V1 完全禁止超收/超发：采购入库 ≤ 未入库数量；销售出库 ≤ 可出库数量；生产入库 ≤ 未完成数量。不做超收、超发容差。
I. MRP 供应方式选择（冻结）
物料档案预设默认供应方式：采购 / 自制 / 采购+自制。MRP 计算后，若为「采购+自制」，在 MRP 确认页逐条选择最终方式。
J. 审批与数据权限补充（冻结）
审批不通过 = 打回「待提交」，不单独设置「审批未通过」状态：待提交 → 审批中 → 已审批；审批中 → 待提交（打回）。
数据权限未明确配置时，默认回退到「本人」，只能查看本人创建/负责的数据；管理员可配置为本人 / 本部门 / 全部。
基础资料停用后，历史单据正常查看、查询、导出；仅不能再用于新建业务单据。历史数据不因基础资料停用而失效。
K. UI 规范冻结
系统名称：Token 制造。主色调：红色（参考企业级 ERP 参考图风格）。
UI 参考《ERP2.docx》布局与组件风格：左侧垂直主菜单、顶部操作、筛选区、表格、右侧行操作、单据基本信息卡片+明细表+附件+审批区。具体内容以本文档为准，不照抄参考图的复杂模块与密集统计卡片。
左侧一级菜单仅 8 个：首页/驾驶舱、销售、采购、生产、MRP、库存、质量、系统管理（菜单稀疏属预期，不做参考图级别的多模块扩展）。
UI 原型与设计稿由开发方产出，以本文档业务范围为准。
