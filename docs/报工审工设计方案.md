## 一、业务流程设计

### 1.1 报工整体流程

```
生产工单（未开始）
   └─ 工单开始（点击「开始」）→ 工单状态 → 执行中
         └─ 工序开始（点击「工序开始」）→ 该工序进入「进行中」
               └─ 报工（录入数量/良品/不良品/工时）→ 生成报工记录
                     ├─ 工序未完成 → 可继续报工
                     └─ 工序已完成（点击「工序已完成」）→ 进入审工
                           └─ 审工（审核通过/反审核）
                                 └─ 全部工序完成 → 工单「已完工」
```

### 1.2 核心概念

- **工单**：生产任务，含多道工序（来自工艺路线）
- **工序**：工单下的具体加工步骤，是报工的最小单元
- **报工**：工人完成某工序后，登记完成的良品数、不良品数、工时
- **审工**：审核报工数量是否属实，通过后才正式计入完工

## 四、状态流转

### 4.1 报工单审核状态

```
pending（待审）→ approved（已审）
        ↘ rejected（驳回）→ 可重新报工
approved → 反审核 → pending
```

### 4.2 工单状态联动

| 事件 | 工单状态变化 |
|---|---|
| 点击「工单开始」 | 未开始 → 执行中 |
| 所有工序报工完成并审工通过 | 执行中 → 已完工 |
| 成品入库完成 | 已完工 → 已完成 |
| 计划结束时间已过仍未完工 | 执行中 → 已逾期 |

### 4.3 报工 ↔ 完工数量联动（已实现，口径已确认）

- **完工口径（已确认）**：只有**最后一道工序**的良品才累加到工单 `completedQty`（成品数量）
- 报工审工通过：若报工工序是工艺路线的最后一道工序，则良品数累加（上限为计划数量）
- 报工反审核：若为最后一道工序，从 `completedQty` 扣减（下限为 0）
- 报工校验：工单必须「已审批 + 执行中（producing）」
- 无工艺路线的工单（单工序场景）：按「是最后工序」处理

### 4.4 排产校验（已实现）

- 排产校验：工单必须「已审批」
- 机台时间冲突检测：同一机台时间重叠的排产会被拦截

## 五、与现有体系的对接

| 对接点 | 说明 |
|---|---|
| 工单 | 复用 `production_order`，扩展状态机（7态） |
| 工序 | 复用 `process` 表 + 工艺路线 `process_route_item`（工单展开工序） |
| 车间/机台 | 复用 `workshop` / `machine`（工单已有 workshop_id/machine_id） |
| 编号 | 报工单号 `BW + 日期 + 流水`（复用 CodeGenerator） |
| 库存 | 报工不直接改库存（良品入库走入库单，避免破坏 V1 库存一致性） |

## 六、关键设计决策（需要你确认）

### 决策1：报工粒度
- **方案A（推荐）**：按「工单 + 工序」报工（每道工序单独报工）
- 方案B：按「工单」整体报工（不细分工序）

### 决策2：报工是否扣减/增加库存
- **方案A（推荐）**：报工只记数量和工时，**不动库存**；良品入库走独立的入库单（保持 V1 库存一致性）
- 方案B：报工自动生成良品入库（更自动化但复杂，需处理库存锁）

### 决策3：工单展开工序的来源
- **方案A（推荐）**：工单关联工艺路线后，按工艺路线明细展开工序（`process_route_item`）
- 方案B：工单关联 BOM，按 BOM 的 `process` 字段展开（但 BOM 工序是字符串，需先改成 process_id 外键）

### 决策4：是否先做「BOM 工序外键」改造
- 报工要按工序展开，如果工单走工艺路线（决策3选A），则 BOM 工序外键可以后做
- 如果选 BOM 展开，则必须先改 BOM 的 `process` 字符串为 `process_id` 外键
