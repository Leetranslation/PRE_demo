# Token 制造 ERP 第二版开发规划（V2 基准修订版）

> 版本：V2.0 规划｜用途：第二版开发的统一依据
> 决策结论：**突破 V1.0 冻结边界，向钉铛智造看齐；但 V1.0 的「技术冻结规则」必须全部继承，不得推翻。**

---

## 〇、基准声明（最重要）

第二版遵循「**双层基准**」：

1. **技术地基（V1.0 冻结规则，永久生效，不可推翻）**：编号规则、金额/税额差额法、精度规范、审批与反审核规则、MRP 计算规则、库存一致性/并发/幂等、禁止自审、逻辑删除/停用策略等。这些在 V1 代码中已落地且质量较高，第二版**必须原样继承**。
2. **范围边界（V1.0 冻结边界，本次突破）**：V1 明确「不做的模块」（复杂 MES、财务、外协、OA、人力、多级审批等），第二版**按钉铛智造方向逐步放开**。

> ⚠️ 铁律：突破的是「做什么」，不是「怎么做」。凡涉及库存、金额、审批、编号、幂等、并发的既有规则，一律沿用 V1.0 文档冻结结论，不得因扩范围而破坏。

## 一、V1.0 冻结规则（第二版必须继承的技术地基）

以下规则摘自 `ERP系统V1.0_完整产品需求与系统设计文档_修改版.docx`，已在 V1 代码落地，第二版新模块同样适用：

### 1. 编号规则
- `业务前缀 + yyyyMMdd + 4位流水`，按日重置（每天 0001 起）
- 删除单据编号永久作废、不复用
- 已有前缀：WL物料 / CP产品 / KH客户 / GY供应商 / SO销售订单 / PO采购订单 / MO生产工单 / BOM / QC质检单 / RK入库单 / CK出库单 / MRP
- **新模块前缀需延续此规则新增**（如外协 WX、报工 BW、排产 PC 等，需在文档登记）

### 2. 金额与精度（冻结，差额法）
- 数量 6 位、单价 6 位、金额/税额/价税合计 2 位、税率 2 位
- 单价默认含税；默认税率 13%（可配置，明细可改）
- **税额差额法倒挤**：`价税合计 = round(含税单价×数量,2)`；`不含税 = round(含税金额÷(1+税率),2)`；`税额 = 价税合计 − 不含税`
- 金额由后端重算，前端金额不作为最终可信数据

### 3. 审批与反审核
- 审批状态：`待提交 → 审批中 → 已审批`；V1 只做「审批通过 + 反审核」，无驳回
- 审批状态与业务状态**分离维护**
- 默认禁止自审（`allow_self_approve` 参数可开）
- 反审核后回「待提交」；**已产生下游业务/库存事务的单据禁止直接反审核**
- 审批通过后核心字段锁定（编号、客户/供应商、明细、来源单据）

### 4. MRP 计算规则
- 净需求 = `max(0, 毛需求 + 安全库存 − 可用库存 − 在途供应)`
- 可用库存 = 实际 − 预留 − 待检 − 不合格
- 在途供应只计入「需求日期前可到货/完工」的供应
- 多层 BOM 展开（防循环）、计入损耗率（`需求=数量×(1+损耗率)`）
- 提前期按自然日倒推建议日期

### 5. 库存一致性 / 并发 / 幂等
- 台账 + 流水事务一致，禁止绕过库存服务直接改数量
- 行级悲观锁 + Redis 分布式锁 + 唯一索引兜底（`InventoryService`）
- 入库/出库/领料/退料等关键操作传 `requestId` 幂等
- 完全禁止超收/超发（采购入库≤未入库、销售出库≤可出库、生产入库≤未完成）

### 6. 其他冻结
- 逻辑删除：基础资料「启用/停用」，被引用的禁止停用；历史数据不因停用失效
- 危险操作二次确认、批量操作逐条返回结果
- 采购/生产统一用「入库」，不用「收货」
- 产品与物料分离
- 权限码 `模块:资源:操作`，`menu`/`button` 两类，明细查询不单独授权

## 三、工单状态机升级（第二版重点）

V1 生产工单业务状态为 `待生产→生产中→部分完成→已完成`（4 态）。第二版升级为钉铛智造的多态状态机，但**审批状态仍沿用 V1 的 `pending/approving/approved` 三态分离**。

### 主状态机（决策：复用 `bizStatus` 字段扩展，不新增字段）

**已拍板**：在现有 `bizStatus` 字段基础上直接扩展状态值，不新增主状态字段。

> **权威依据（钉铛智造文档 7.5 节）**：工单列表 Tab 明确为 7 个状态：
> `全部工单 / 未开始 / 执行中 / 快逾期 / 已逾期 / 已完成 / 已作废`

新 `bizStatus` 枚举（7 态）：

| bizStatus 值 | 含义 | 说明 |
|---|---|---|
| `pending` | 未开始 | V1 原值「待生产」语义对齐 |
| `producing` | 执行中 | V1 原值「生产中」 |
| `near_overdue` | 快逾期 | **新增** |
| `overdue` | 已逾期 | **新增** |
| `finished` | 已完工 | **新增** |
| `completed` | 已完成 | V1 原值「已完成」 |
| `voided` | 已作废 | **新增** |

> 迁移规则：V1 已有数据 `pending/producing/completed` 原值不变，`partial`（部分完成）映射为 `producing`（执行中），追加新值，保证历史数据兼容。
> 快逾期/已逾期由「计划结束时间 + 当前时间」动态判定或定时任务刷新。

### 状态-操作矩阵（权威依据：钉铛文档 7.5 节）

| 状态 | 行内操作按钮 |
|---|---|
| 未开始 | 编辑、复制、开始、详情、删除、领料、生成计划、完工 |
| 执行中/快逾期/已逾期 | 复制、撤回、结束、详情、领料、入库、按单代报、完工 |
| 已完工 | 复制、详情 |
| 已完成 | 复制、详情、领料、作废、入库、完工、反完成 |
| 已作废 | 复制、详情、删除、完工 |

### 子状态字段（`production_order` 表新增，与 bizStatus 并列）

| 新字段 | 取值 | 默认 |
|---|---|---|
| `finish_status` | unfinished 未完工 / finished 已完工 | unfinished |
| `inbound_status` | none 未入库 / partial 部分入库 / all 全部入库 | none |
| `issue_status` | none 未领料 / partial 部分领料 / all 全部领料 | none |
| `qc_status` | not_needed 无需质检 / none 未质检 / pending 待质检 / ing 质检中 / qualified 合格 / unqualified 不合格 | not_needed |
| `machine_status` | unlinked 未关联 / linked 已关联 | unlinked |
| `urgency` | normal 普通 / urgent 紧急 / very_urgent 非常紧急 | normal |

> 子状态字段名与 V1 命名风格一致（snake_case 小写），沿用 BaseEntity 审计字段，不破坏现有结构。

## 四、第一版代码范式（编码铁律，新模块必须照此套模板）

### 后端
| 维度 | 约定 |
|---|---|
| 分层 | controller / service / dto / entity / mapper |
| 返回 | `Result<T>` + `PageResult<T>`（page/pageSize/total/records） |
| 分页 | MyBatis-Plus `Page` + `LambdaQueryWrapper` |
| Controller | `@RequestMapping("/api/模块/资源")` + `@PreAuthorize` |
| 接口 | `GET /list`、`POST /create /update /submit /approve /unapprove /status`，id 用 `@RequestParam` |
| Service | `@Service` + `@RequiredArgsConstructor` + `@Transactional` + `BizException` |
| 编号 | `codeGenerator.next("前缀")` |
| 实体 | 继承 `BaseEntity`（自动填充审计字段） |
| 权限码 | 登记到 `DataInitializer.PERMISSIONS` |

### 前端
| 维度 | 约定 |
|---|---|
| 布局 | `el-card` → 筛选 `el-form inline` → 工具栏 → `el-table` → `el-pagination` |
| 表格 | `border stripe` + `selection` 复选 + 操作列 `fixed=right` link 按钮 |
| 状态 | `el-tag` + `xxxText()`/`xxxTagType()` 映射函数 |
| 弹窗 | `el-dialog` + `form` reactive + `openDialog(row?)` |
| 选择器 | `MaterialPicker` / `ProductPicker` + `@select` |
| 导出 | `useExport(columns, filename)` |
| API | `@/api/xxx.ts` + `PageResult<T>` |
| 路由/菜单 | `@/router/index.ts` + `@/layout/index.vue` 同步添加 |
| 多页签 | 已有 `tabs.ts`（上限15）+ `TagsView.vue` + keep-alive |

## 七、开发约定补充

1. 每个新模块交付顺序：**建表 SQL → Entity/Mapper → DTO → Service → Controller → 前端 api.ts → 路由+菜单 → 页面 vue**。
2. 每个新模块权限码同步登记 `DataInitializer`。
3. 新编号前缀（外协 WX、报工 BW、排产 PC 等）在本文档登记后再使用。
4. 涉及库存/金额/审批的新模块，必须复用 V1 的 `InventoryService` / 差额法 / 审批模式，不另造轮子。
5. 单据页复用 `MaterialPicker`/`ProductPicker`/`useExport`。
